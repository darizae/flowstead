# Flowstead implementation agent routing

**Primary route:** read `docs/planning/HANDOFF_SEQUENCE.md` for the **next locally eligible task**, confirm completed predecessors; OMP owns ordinary checkout/test setup, then read only that task file, `docs/planning/IMPLEMENTATION_SPEC.md` and its initial read set. The existing bounded local implementation scope needs no repetitive per-task owner approval; external/cloud/public/cost/architecture changes remain separately gated. Do not re-run completed stages or queue a dependent task before its actual predecessor.

This repository owns Flowstead application API, versioned PostgreSQL schema/migrations, bounded synthetic importer, Supabase Auth adapter, React UI, forecasts and permission-scoped exports. The independent upstream is `darizae/flowstead-sim`; pin an immutable tested generator version/commit, never vendor its code. **PostgreSQL-only for MVP; no AWS S3**, object-store setup or persistent report file store. D-040 is owner-approved; cloud writes, new `flowstead-demo`, Auth invitations, hosting and DNS still require separate exact approval.

Use root `justfile` local commands only when real recipes exist. Preserve uncommitted owner work, secret boundaries and tight changed-path/lockfile preflight; test first on the Mac. Worktree isolation is not OS sandboxing. No DHI-derived published data, forced Git history rewrites, arbitrary model-supplied shell, unbounded export or unrelated refactor.

**OMP implements and owns the PR lifecycle.** Its planned follow-up is independent review, corrections, exact-final-SHA local tests, policy-authorized merge and synchronization of source-controlled task statuses; do not block ordinary task dispatch on that future enhancement. Until it handles reviews unattended, leave outstanding PRs in the existing review workflow, never fabricate approval. The control plane holds execution receipts, not private decisions or a second product plan.
