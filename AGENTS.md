# Flowstead implementation agent routing

**Primary route:** read `docs/planning/HANDOFF_SEQUENCE.md` for the **next locally eligible task**, confirm its listed predecessors and actual Mac/OMP preflight, then read only that task file, `docs/planning/IMPLEMENTATION_SPEC.md` and its initial read set. The existing bounded local implementation scope needs no repetitive per-task owner approval; external/cloud/public/cost/architecture changes remain separately gated. Do not queue merely because a file exists.

This repository owns Flowstead application API, versioned PostgreSQL schema/migrations, bounded synthetic importer, Supabase Auth adapter, React UI, forecasts and permission-scoped exports. The independent upstream is `darizae/flowstead-sim`; pin an immutable tested generator version/commit, never vendor its code. **PostgreSQL-only for MVP; no AWS S3**, object-store setup or persistent report file store. D-040 is owner-approved; cloud writes, new `flowstead-demo`, Auth invitations, hosting and DNS still require separate exact approval.

Use root `justfile` local commands only when real recipes exist. Preserve uncommitted owner work, secret boundaries and tight changed-path/lockfile preflight; test first on the Mac. Worktree isolation is not OS sandboxing. No DHI-derived published data, forced Git history rewrites, arbitrary model-supplied shell, unbounded export or unrelated refactor.

**OMP implements/tests and must obtain an **independent, separate reviewer** at the exact PR head; the implementation worker cannot self-approve. Unattended review/merge may replace the former normal-chat pause only **after actual OMP live acceptance and explicit repository-scoped policy**, otherwise stop at `review_ready`. Exact-final-head Mac verification, authorized merge and evidence-based task-status synchronization remain mandatory. The control plane holds execution receipts, never private owner decisions or an alternative product plan.
