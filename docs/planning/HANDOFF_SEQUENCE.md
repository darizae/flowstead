## Completion rules

An existing bounded **local** task becomes READY automatically only after its predecessor and readiness evidence is confirmed (checkout/branch, applicable tools and real `just` commands, manifest/lockfile/path closure, available model and required tests); use one minimal dispatch receipt with the task file path and source commit. A static task filename/status or a free-form Issue is not evidence of completion. Keep review, exact-final-SHA tests, merge and approved status reconciliation as distinct gates. For hosted, public, secret, cost or architecture-changing tasks, obtain the separate explicit owner approval named above. Milestone Markdown/routing hygiene remains required (006, 013, 018). No shadow planning queue; this sequence and [`IMPLEMENTATION_SPEC.md`](IMPLEMENTATION_SPEC.md) remain authoritative.
