## Implemented in source

- **Real invite-only login:** Frontend `Sign in` now opens an accessible
  email/password modal. `SupabaseAuthProvider.signIn` calls
  `signInWithPassword`; successful Auth sessions are routed into the existing
  authenticated FastAPI client; error messages are non-enumerating. The offline
  provider fails closed, except for deliberately injected tests.
  Password fields are cleared on close/failure; there is no signup UI.
  Existing cache partition and sign-out behavior remain in place.
- **Security correction:** `read_forecast_job` now requires
  `forecast_jobs.requested_by = principal.sub` **as well as** a Plant
  access grant. Previously same-Plant users could read a requester's
  job status if they obtained its correlation ID. A disposable-DB
  integration regression test was added but cannot be marked hosted PASS
  until executed in a real DB and the patched API is deployed.
- **Repeatable bounded tests:** `scripts/hosted_operator_smoke.py` reads the
  two owner-controlled, `0600` test-password files using a no-follow file
  descriptor, gets real Supabase JWTs **in memory only**, checks both
  Plant access sets and denied cross-Plant requests, and optionally sends
  **exactly one** forecast POST followed by a bounded completion poll.
  `--auth-only` requires no OCI API. Test code emits neither credentials nor
  tokens. `frontend/e2e/hosted_operator.live.mjs` checks both UI sign-ins
  using ephemeral, non-persistent Chrome contexts; it intentionally disables
  screenshots, downloads and traces and redacts errors.
- **CI:** `.github/workflows/ci.yml` checks Python units, frontend typecheck,
  unit tests/build, and docs with read-only GitHub permissions and no
  deployment credentials. Real GitHub-hosted execution awaits push.
- **Backlog:** T-016/017/019/020 and release docs are refreshed to distinguish
  the previously observed deployment from present availability.

## Later live acceptance: authenticated API, browser and persisted forecast

This **supersedes the preceding blocked/zero-job observations**. All tests below
ran on the existing approved synthetic demo; passwords stayed in owner-only
local files and JWTs stayed in ephemeral process/browser memory. No token,
password, browser trace, screenshot or session cookie was committed or printed.

- **JWT interoperability fixed and shipped to Oracle:** Real Supabase ES256
  tokens include `sub`, `iat`, `iss`, `aud` and `exp`, but may omit
  `nbf` (not before). The API previously required `nbf`, incorrectly
  returning 401 for legitimate operator JWTs. The revised verifier keeps
  signature, key/algorithm, issuer, audience, issued-at and expiry mandatory
  and validates `nbf` **if present**. Real ES256 JWKS verification passed
  for both existing operators. Regression tests cover optional `nbf`,
  future `nbf` rejection and missing expiry. The patched `auth.py` was
  transferred with SHA256 verification to the existing VM and FastAPI restarted.
- **Scoped API E2E PASS:** Both test users authenticated with real password
  grants. Operator A's private Plant list was exactly `plant-01,plant-02`;
  B's was exactly `plant-03,plant-04,plant-05`. All tested other-Plant
  latest/PDF endpoints denied access with non-enumerating 404. The
  bounded smoke sent **exactly one** real forecast request for A's Plant 01,
  received 202, and denied B's forecast-status read with 404.
- **Forecast pipeline PASS:** API accepted the request, outbox/NATS/worker
  delivered and completed it, and the persisted 12-hour forecast contained
  hour numbers 1–12 in order. Independent Supabase SQL then observed
  `app.forecast_jobs`: **one completed**;
  `app.forecast_issuances`: **one**;
  `app.message_outbox`: **seven published**, zero pending;
  `app.message_failures`: **zero**.
- **Real UI E2E PASS:** The production Vercel build at Git SHA
  `1d108b220272` was READY at `https://flowstead.darizae.dev`.
  An isolated Playwright Chromium browser loaded the actual hosted Sign in
  dialog, authenticated both existing operators using their owner-local
  password files, observed exactly **two** and **three** authorized Plant
  rows, signed out each and observed the public **five** Plant rows.
  Each browser context was ephemeral (no storage export, screenshots or traces).
- **Boot-recovery flaw fixed:** After Oracle's one graceful SOFTRESET,
  NATS and Caddy returned, but systemd `flowstead-api` and
  `flowstead-worker` had been `disabled` and remained inactive.
  Enabled both units on the **existing** guest and started them without
  regenerating secrets or replacing compute. Subsequent reads confirmed
